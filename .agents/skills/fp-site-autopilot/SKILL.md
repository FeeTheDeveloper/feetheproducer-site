# Fee The Producer site autopilot

Adapted from Plugin Autopilot 0.7.0 workflow compilation and host-workspace principles. This is a repository-local maintenance workflow, not a plugin-package conversion or automatic publishing process.

1. Read root AGENTS.md and the current task. Verify repository origin, branch, working tree, package scripts, relevant routes, and supplied assets. Locate actual evidence before choosing files to edit. Preserve existing user changes.
2. Select the smallest workflow: [Site Studio](../fee-producer-site-studio/SKILL.md) for implementation, [motion](../fee-producer-web-3d-motion/SKILL.md) for 3D/animation, and [catalog](../fee-producer-site-catalog/SKILL.md) for releases or external media links.
3. Record a concrete acceptance target. Read/list/search first; use focused patches for authorized changes and shell commands for inspected repository checks. Do not introduce a new runtime, provider, or architecture just because a workflow mentions it.
4. Implement through a complete reviewable result. Preserve canonical assets, semantic navigation, useful static content, contact truth, and public/private separation. Mark generated art and unknown facts accurately.
5. Build and run the checks relevant to the change. For a material UI rebuild, use production build, typecheck, lint, responsive browser checks, motion/fallback tests, link validation, and screenshots. For documentation-only changes, inspect links, frontmatter, instructions, and scope; do not claim application behavior changed.
6. Review the final diff, tests, and artifacts. Report source revision, branch, changed paths, commands/results, preview location, limitations, and release state. No fabricated executions or provider receipts.
7. Stop only dependent work for a real missing input, conflicting change, or failed check; continue useful independent work. Fix failures before claiming verification. Respect current authorization for commits/releases and distinguish local completion from external delivery.

Do not bundle the public website into a new installable plugin unless the user explicitly requests that separate outcome. Updating repo skills does not update the saved Fee The Producer account plugin; an account update needs its verified plugin identity, current source, guarded release update, and readback through the appropriate plugin tools.
